# OpenFeed Studio — 产品需求与体验规范

**版本：** 0.2 设计基线 · 2026-10-21  
**定位：** 可自托管、数据可迁移的 Web-to-RSS 工作台；服务金融研究、招聘监控和一般资讯收集。  
**免责声明：** 目标指标是设计验收门槛，不代表已实现或在真实站点上验证通过。

## 1. 核心问题与产品边界

PolitePol/PolitePaul 免费订阅条数下降使用户依赖于外部 SaaS 的数量上限；与此同时研究机构站点变化频繁，新闻列表、筛选页、招聘系统的 DOM/接口存在显著差异。我们将「创建 Feed」与「抓取网站」「管理更新状态」明确分离，以减少迁移成本和重复订阅。

**必须做到：** 快速发现原生 RSS、可视化生成静态网页选择器、可手写 CSS/XPath/Feed43 基础规则、逐条验证、标准 RSS 输出、更新历史、可暂停、可移植备份。产品不使用人为订阅条数限制，但实际容量取决于设备、站点限流与抓取代价。

**不承诺：** 任意网站 100% 可抓取；绕过 CAPTCHA、付费墙或访问控制；第三方站点绝对实时；当前 v0.2 已经解决复杂 JavaScript 页面。

## 2. 产品对象

- `Source`：原始新闻栏目 / 职位列表 / 检索结果 URL。注意一个机构可有多个来源。
- `Recipe`：版本化提取声明（抓取模式、重复项、字段映射、分页和过滤策略）。不同引擎可共用外部规范，但必须持久化引擎版本。
- `Feed`：订阅者可访问的稳定 URL 与发布策略；不必与 Source 一对一（未来支持组合 Feed）。
- `Entry`：文章或职位的事实记录，保留 `first_seen_at` 与 `published_at`，GUID 独立于排序和标题。
- `FetchRun`：抓取诊断与错误、提取数和新增数。

## 3. 关键用户旅程

**创建：** 粘贴 URL → 侦察（HTTP、Content-Type、重定向、`rel=alternate`、RSSHub 等可选适配）→ 若有原生 Feed 建议直接订阅 → 否则自动推断候选容器 → 可视化手工修正 → 运行真实提取 → 显示条目/字段置信度/诊断 → 保存 Recipe → 首次抓取 → RSS URL。

**维护：** 总览显示异常与上次成功时间 → 点击 Feed 查看每次运行日志与前几条真实内容 → 暂停/恢复 → 修订规则 → 预览差异 → 保存新规则版本并测试；失败不清空前一次有效结果。

**迁移：** OPML 用于订阅 URL，Recipe Bundle v2 用于规则+源 ID；数据库快照用于条目历史/运行日志。不能只凭 OPML 重建原始网页选择器。

## 4. UI 信息架构

- 概览：源数量、正常数量、条目数量、需要关注的来源；异常优先；最近抓取。
- 源列表：搜索机构/域名、状态筛选、来源类型、最近成功时间、条目数；支持批量管理（目标）。
- 创建抽屉：URL／自动建议／静态网页快照点选／选择器／字段预览／发布状态。
- 详情：已存储条目、运行历史、错误原因、暂停恢复、复制订阅地址。
- 规则高级编辑：CSS、XPath、Feed43 捕获式 DSL；JSONPath/动态浏览器待扩展。
- 数据可移植：OPML、完整 Recipe Bundle、数据库备份说明。

**设计原则：** 高信息密度但避免紧密堆砌；操作反馈需区分「保存成功」「抓取失败」「刷新延迟」「可发布」。默认桌面优先，移动端仍能执行检查与停启。输入、空状态、加载、失败、恢复反馈都应一致。

## 5. 内容质量与 RSS 语义

| 字段 | 优先级 | 策略 |
|---|---|---|
| `guid` | 必须 | 来源内永久链接归一化后哈希；标题改动不改 GUID |
| `link` | 必须 | 原文 URL；不伪造已经抓到正文 |
| `title` | 必须 | 必须非空；去掉不可见空白与 XML 非法字符 |
| `published_at` | 尽可能 | 原文真实时间；无日期不应伪称当天发表 |
| `first_seen_at` | 必须 | 首次被系统发现的时间 |
| `description` | 可选 | 原网页公开摘要；与全文标识分离 |
| `attachment` | 可选 | PDF 确实可访问才输出 enclosure（尚未实现） |

将来的职位数据必须包含职位 ID、企业、城市、岗位生命周期，且岗位“消失”需要连续确认、避免短暂抓取失败引发下线误报。

## 6. Release Gates（未来目标）

- Gate A — 核心：静态页面 + 原生 RSS、Recipe 编辑、Feed 发布、可迁移备份、去重、回退、回归测试。
- Gate B — 研究场景：对 Oaktree / BofA / Gold.org 分别真实验证 3 次抓取，确保原链接、日期与新增文章行为正确。
- Gate C — 动态：KKR 使用 Playwright 或合法公开数据接口，记录成功率、抓取成本与需手工调整的规则。
- Gate D — 招聘：Citi 职位新增/变更/消失语义；猎聘优先官方提醒，明确受安全验证限制。
- Gate E — 运行：48–72 小时持续运行实验（阶段指标）；备份恢复演练；SSRF、异常输入、超时、反爬限制、信息泄露测试。

**不把固定数字 300 条视为实测容量。** 在真实目标域名、获取频率与机器配置上做基准测试之后才公布容量等级。
