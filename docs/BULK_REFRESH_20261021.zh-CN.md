# 批量刷新与工程核查

## 本次可运行增量
- `POST /api/feeds/bulk-refresh`：管理员 Token 鉴权，接收 1–30 个不重复的 Feed ID。
- 先验证所有来源存在，避免对部分合法来源执行后才发现错误 ID。
- 最多三个并行请求；每个来源复用原有抓取锁、域名限速、网络并发控制。
- 单个来源抛异常不影响剩余来源，结果按输入顺序返回，包含每条结果/错误。
- Web 管理台可对当前搜索/筛选下的已启用来源执行刷新（最多前 30 条）。
- 操作反馈区分成功更新、延后/繁忙、失败。

## 架构注意
批量刷新仍是一个同步 HTTP 请求；批次最多 30 条以限制浏览器等待和超时风险。规模更大时需独立持久化批量作业队列及进度查询，而不是简单扩大请求大小。
