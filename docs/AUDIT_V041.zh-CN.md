# OpenFeed Studio v0.4.1 独立源代码审计与产品差距清单

日期：2026-10-21。范围：项目现有 FastAPI/SQLite、HTTP 和 Browser fetch、前端编辑器、分页、调度、备份、RSS 生成、自动化测试与 Docker 配置。**这是静态代码审计和离线自动化测试，不是渗透测试、云端部署测试或任何外部网站的可用性认证。**

## 结论与风险评级

- **发布结论：NO-GO（不得称为生产版或对公网多用户开放）。** 仅适于私有、受信任网络中的静态 Feed 原型试用。未执行正式生产部署。
- **可视化：部分完成，不是 PolitePol 功能等价复刻。** 已有静态 HTML 快照中的点击选元素、文章重复容器推断和相对 CSS 建议；测试覆盖合成 HTML 的 Chromium 交互。但不支持真实跨域网页内直接点击、高保真样式/交互、浏览器扩展、完整 XPath 可视化选取、JS 触发加载后选取、登录态、iframe 场景、移动端编辑完整体验；也没有真实金融网站的人工验收。
- **本轮证据：** 基线 53/53；修补后 57/57 自动化测试通过；JS 语法检查通过。本环境未实际完成 Docker build、真实目标联网 E2E、Reader 云端订阅或 7×24 稳定性压测。

## v0.4.1 实施修改与复核

1. `openfeed/pagination.py`：分页模式从来源 URL 固定可信 origin，禁止第一页发生跨 origin 重定向后静默把重定向站点当作新的 origin；规范化 HTTP(S) 默认端口，避免 `https://host` 与 `https://host:443` 误判。
2. `static/app.js`：Lock 按钮除了显示验证界面，也清除 sessionStorage 中的管理员 Token、输入框和内存中的来源列表，降低本地共享设备误访问风险。**这不是服务器端 Token 吊销，仍要单独实现服务端会话机制。**
3. 修正检查结果中的过时“pagination 未实现”文案，以及 README 中静态分页能力与缺失的 JS 分页之间的区分。
4. 新增 `tests/test_audit_v05.py`，覆盖这些回归检查。合计 **57/57** 离线自动化测试通过。新增测试仍不能替代 Docker、外部站点及安全攻防测试。

## 推荐实施顺序与验收门禁

**第一关：可视化真实网页 MVP**：浏览器扩展跨站点选 + CSS/XPath 规则提取，选 5 个公开样本站跑通，实时样例与字段匹配率可见。

**第二关：真实来源与 Reader**：20 个原始网站建立可复用规则仓库/回归夹具；至少 5 个在 Reader 中真实云端导入、连续更新通过。

**第三关：生产防护**：独立浏览器 Worker 与 egress firewall，Docker build、备份恢复、TLS/认证/反滥用，严格单实例部署或任务租约。

**第四关：研究/招聘产品化**：PDF、搜索结果筛选、职位变化、质量告警、批量工具、多语言及界面打磨。

**不能以“57 个单元测试通过”代替以上四个发布门禁。**
