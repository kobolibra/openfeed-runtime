# OpenFeed Studio v0.5 — 发布前内容质量闸门与差距审计

## 本轮实际交付
- 增加 `openfeed/quality.py`，在文章写入 SQLite 之前校验每条提取记录；拒绝空标题、非公网/非 HTTP(S) 文章链接、超长字段、重复 URL，以及非法发布日期字段类型。
- 对整批无效提取失败关闭（fail closed），让既有的历史 RSS 内容留在数据库中；在抓取运行日志中记录拒绝计数、缺少原始发布日期的数量。
- 新增五项内容质量专项测试；全套回归测试 62/62 通过（仅针对本地和合成输入）。
- 更新 API 应用版本至 0.5.0。保留原 Recipe 格式和稳定 feed ID，故不用数据库迁移。

## 重要限制 / 不可误报
- **可视化没有达到 PolitePol 等价**：仅支持安全 HTML 快照里的点击选取，未实现真实网站扩展、交互式字段联动与动态网页全链路调试。
- Playwright 实验接口有应用层请求预检，但尚未在独立、网络隔离的沙箱部署；禁止对不受信任用户开放此能力。
- Docker 构建、真实研究机构网页抓取、Reader 云端订阅、上百个 Feed 的长期调度未在此轮验证。
- 质量闸门是格式/安全基础检查，**不是**关于来源文章覆盖率或语义正确性的证明。仍须校验 HTML 变更与分页漏抓。
- 已有 admin token 模式仍非面向公网多用户的身份系统；只建议在可信私有网络/带额外鉴权的反向代理后使用。

## 发布门禁（阻断生产上线）
1. 浏览器扩展 + 真实跨站可视化编辑的端到端测试；至少三种网页结构与动态页面。
2. 安全浏览器 Worker 的系统级网络隔离和 SSRF 漏洞验证。
3. 真实来源持续抓取，确保标题、日期、永久链接和动态筛选精度。
4. 公网 HTTPS Feed 被 Readwise Reader 实际成功订阅和刷新。
5. Docker 构建、数据库备份恢复演练、长时间运行与资源测量。
6. 生产会话/鉴权、监控、错误预算、版本升级与回滚测试。

## 推荐验收顺序
Oaktree / BofA / Gold.org（静态栏目） → KKR（动态页面） → Citi（职位生命周期） → Reader 端到端 → 部署与连续运行。
