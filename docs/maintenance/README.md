# 持续维护与多 agent 交接

权威顺序：用户最新明确指令 → 当前实际运行事实 → 当前维护记录 → 历史报告。旧记录不得覆盖新的实测；实测与记录冲突时记录差异并排查。

| 文件 | 用途 |
|---|---|
| CURRENT.md | 一页当前状态、最后改动、下一步；每轮修改后更新 |
| latest-snapshot.json | 最近一次只读运行快照，有时间和源码指纹；不是验收结果 |
| snapshots/ | 历次快照，供比较退化与恢复 |
| ISSUES.json | 稳定问题编号、已知证据、未完成项；不靠聊天找待办 |
| DECISIONS.md | 用户长期约束、删除/合并/暂缓与架构决定 |
| CHANGELOG.md | 追加式维护流水，记录实现、测试、部署、证据与未完成项 |
| LOCAL_RUNTIME.md | 当前 Mac 路径、容器、发布链路及敏感信息位置；迁移时更新 |
| HANDOFF_TEMPLATE.md | 切换 agent 前完成的交接模板 |

快速流程：读入口 → 采集快照 → 对照未完成事项 → 记录本轮任务 → 小范围修改和验证 → 必要部署 → 再采集快照 → 更新记录。

在源码根目录运行：

```sh
python tools/maintenance_snapshot.py
```

脚本只读本机管理API，输出来源状态、调度参数、配置指纹与源码指纹，不导出令牌、完整配方、URL查询或数据库。使用项目已有虚拟环境。令牌默认 `.openfeed-local/admin-token.txt`，也可用 `--token-file` 指向真实位置。失败时返回非零，不覆盖最近成功快照；不能据此启动新栈或替换数据库。

跨 agent 协作：一次只交给一个写入维护者；下一位先核对上一位的交接状态。确需同时修改时，先明确文件/部署所有权，避免两个agent同时部署、刷新批次或改规则。记录“负责人”不构成自动锁，不保证外部工具强制执行。

跨机器：携带完整源码与本目录；数据库另作私密备份。路径和运行位置会变化，先更新 LOCAL_RUNTIME。若创建私有源码仓库，将维护文档与代码一起版本化；当前公共 feeds 仓库不能用作源码交接仓库。

新发现与历史冲突时，不删除旧结论：追加证据并标注已被取代，CURRENT只保留当前有效结论。大型日志、截图、数据库不塞进入口文件；用可定位路径和校验和引用。保留未成功的试验及原因，避免重复消耗。

## 每次转交可直接使用的指令

请维护这个OpenFeed工程。先读源码根目录AGENTS.md，再按docs/maintenance/README.md读取当前状态与上一轮handoffs/latest.md，运行只读快照并核对差异。不要依赖聊天记忆，不重建删除/暂缓来源，不把测试通过当网站验收。维护期间持续更新问题台账与进展；结束或转交前更新记录并执行tools/check_handoff.py，未通过不能宣称交接完成。后续接手者也必须遵守相同规范。

## 交接检查的实际边界

`python tools/check_handoff.py` 验证必需文件、问题编号、证据/下一步字段、24小时内快照、源码指纹、交接记录是否晚于状态文件。它不会验证日志是否真实、不会证明部署镜像与源码相同，也不能强迫忽略AGENTS的agent。实际镜像与部署验证必须由维护者记录。若引入私有源码仓库，可再将检查集成CI/分支保护；目前尚未配置此类强制规则，不得声称已启用。
