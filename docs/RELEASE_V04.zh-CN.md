# OpenFeed Studio v0.4｜工程交付与质量门禁

日期：2026-10-21。**状态：可运行的个人单管理员工程原型；未达到公网生产部署或全量真实网站迁移标准。**

## 一、本次变更清单

| 领域 | 代码与行为 | 失效保护 |
|---|---|---|
| 研究列表分页 | `openfeed/pagination.py` 根据显式 CSS `next_selector` 跟随最多 3 页 | 限定同源 HTTPS/HTTP 与端口、不可跨域跳转、检测循环、页面间等待、整批失败不落库 |
| 去重与容量 | 同一轮跨页原文 URL 去重、最多收集 300 条，公网 RSS 仍只展示最多 100 条最近记录 | 输入规则限制、超过上限记录诊断；不假装无限抓取 |
| 规则版本 | `feed_revisions` 保存 40 版配置快照，包括规则、来源、更新时间、启停状态 | 可通过后台回滚；回滚本身产生新版本；曾存有文章的 Feed 禁止回滚到不同源 URL |
| 旧版升级 | SQLite 增量建表并为旧 Feed 保存 `migrated` 初始版本 | 原 Feed ID、抓取日志、文章 GUID 不改变；保留原 SQLite WAL 与事务规则 |
| 并发一致性 | 每次抓取读取 `recipe_revision`；提交时在 SQLite 事务内比对最新版本 | 当抓取过程中规则被修改，返回 `stale` 且不提交旧结果，不破坏已有 RSS |
| 健康与运维 | 运行日志记录抓取页数/条目数，抓取调度生命周期优雅清理 | 关闭前等待在途任务或取消，防止对已关闭数据库写入 |
| 产品界面 | 新增分页规则字段、最多抓取页数、规则版本历史及恢复操作 | 需要用户显式确认；预览只抓首页并明确提示 |

## 二、范围与验收方法

- Python 业务逻辑：完整 `pytest` 回归（包含以前的 40 项，以及 v0.4 新增安全、分页、恢复、并发测试）。
- Browser UI：实际 Chromium 中执行页面原生 JavaScript，透过 ASGI 桥调用真正 FastAPI + SQLite；模拟研究站点 HTML，测试从点选、规则保存，到编辑坏规则、历史回滚和 RSS 保留的流程。
- 真实网络：**未完成**。该工作容器对公网 DNS 请求失败，不能据此宣称 Oaktree、BofA、KKR、Citi 等已通过实际抓取。
- Docker：**未完成**。当前环境无 Docker 命令，`compose.yaml` 只能进行静态检查，不等于真实镜像构建验收。
- Readwise Reader：**未完成**。标准 RSS XML 本地解析校验通过；Readwise 云端添加、轮询与去重仍需公网 HTTPS 实测。

## 三、迁移兼容承诺

1. 使用 v0.3 原有的 `/data` 数据卷升级到 v0.4，启动数据库时会新建 `feed_revisions` 并补一条旧配置快照。**升级前务必下载完整 SQLite 备份。**
2. 不更改 `/rss/{id}.xml` 路由，也不更改原来的 Feed ID；对已存在文章的原文链接 GUID 不重新计算。
3. Recipe Bundle v1/v2 保持导入兼容，新字段 `next_selector` / `max_pages` 属于旧规则的可选字段，旧规则默认为单页。
4. 使用新版本前先在副本数据库上执行 `python -m pytest -q`，再验证源创建/更新、历史还原以及上一次成功 RSS 不被清空。

## 四、下一阶段按风险优先的开发与发布门禁

**P0：真实网站端到端验证。** 在有正常公网 DNS 的运行环境，对 Oaktree、Bank of America Institute、World Gold Council、AQR、CEPR 等逐条获取 HTML/RSS；保留 HTTP 响应特征、候选规则、字段准确率、重复抓取及最新文章增量的可复现实录。遇到验证码/访问限制必须标记失败或替代来源，不得宣传绕过。

**P0：动态浏览器隔离。** 独立 Browser Worker，容器/宿主机层同时屏蔽 RFC1918、loopback、link-local、云元数据服务及内部 DNS；有流量配额、浏览器实例清理、下载限制、进程内存上限、模拟内网请求渗透测试，才允许公网实例开启。现行 `browser.py` 仍为默认禁用的实验模块。

**P1：生产观测与灾备。** 72 小时真实运行、Docker build 与版本锁定、数据备份恢复演练、缓存命中率、失效重试、查询性能基准、规则变更审计、429/403 分析及管理员鉴权强化。

**P1：高级网页交互。** 真正跨站选择器浏览器扩展、动态列表加载、有限状态的分页 API、职位新增/编辑/下线事件模型、PDF 发布发现和报告源适配。

**P2：全量迁移。** 用户提供的 URL 原始清单去重、识别栏目关系、筛选参数持久化、官方 Feed 优先，分类输出已验证/需手动/需动态/访问受限，而不是以“录入 URL 数量”冒充成功源数。

## 五、面向最终产品的否决条件

- 未通过真实外部来源测试时，不得称「兼容所有网站」。
- 不能把免费软件等同于免费公共云浏览器资源或无限运行能力。
- 不能将实际未启用的浏览器 Worker、PDF 抓取、招聘生命周期、RSSHub 适配写成已完成功能。
- 任何页面抓取错误都不应清空最后一次成功内容；任何更新中的 Recipe 改动都不得引发旧内容混源。
- 所有管理员写入接口保留鉴权；生产出站仍需要宿主网络策略，应用 DNS 校验不替代物理隔离。
